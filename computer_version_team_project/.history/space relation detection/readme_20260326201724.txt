第3部分：空间关系分析
这是最关键的一步！我们要让系统判断：

手在物体的哪一边（左？右？上？下？）
手和物体的距离（近？远？）
是否可以抓取（手和物体足够接近吗？）
原理简解
回想一下：

手部检测得到的是：手指尖的坐标 (x, y)
物体检测得到的是：物体边框的坐标 (x1, y1, x2, y2)
通过比较这些坐标，我们就能判断相对位置。

比如：

Code
如果 手的x < 物体的x ：手在物体左边 → 说"向右移动"
如果 手的x > 物体的x ：手在物体右边 → 说"向左移动"
如果 手的y < 物体的y ：手在物体上面 → 说"向下移动"
如果 手的y > 物体的y ：手在物体下面 → 说"向上移动"

问题总结
1. hand_object_combined_final.py
问题	原因	解决方案
FileNotFoundError: No such file or directory: 'yolov8n-hand.pt'	工作区中不存在 yolov8n-hand.pt 模型文件，且代码中的"自动下载"逻辑无效（YOLO('yolov8n-hand.pt') 不会自动下载非官方模型）	改为优先加载 yolov8n-hand.pt，不存在时自动回退到已有的 yolov8n-pose.pt（通过手腕关键点估算手的位置）
2. hand_object_mediapipe_final.py
问题	原因	解决方案
hand_landmarker.task 文件不存在	脚本目录下没有 MediaPipe 手部模型文件	从 Google 官方源下载：https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task
yolov8n.pt 找不到	模型只在项目根目录，脚本在子目录 space relation detection/ 里用相对路径 'yolov8n.pt' 加载	将 yolov8n.pt 复制到脚本所在目录
3. hand_object_mediapipe_final_yolom.py
问题	原因	解决方案
Cannot find hand_landmarker.task	脚本使用相对路径 'hand_landmarker.task'，但从项目根目录运行时，工作目录不是脚本所在目录	用 os.path.dirname(os.path.abspath(__file__)) 构造绝对路径，使脚本从任意目录运行都能找到模型
同理 yolov8m.pt 也有路径问题	yolov8m.pt 在项目根目录，脚本在子目录	用 os.path.dirname(base_dir) 获取项目根目录，拼接出正确的模型路径
共性根因
所有问题归结为 两类：

模型文件缺失 — yolov8n-hand.pt 不是 Ultralytics 官方模型，无法自动下载；hand_landmarker.task 需要手动从 Google 下载。
相对路径依赖工作目录 — 脚本中写 'model.pt' 这样的相对路径，从不同目录运行时会找不到文件。统一改为基于 __file__ 的绝对路径即可彻底解决。

最后采用hand_object_mediapipe_final_yolom.py这一份
